## 1. プロジェクト概要

Mac上で動作する、会議録音・文字起こし用のCLIツール `meeting-cli` を実装する。

ユーザーがコマンドを実行するとマイク録音を開始し、停止操作後に音声ファイルを保存する。その後、OpenAI Whisperをローカル実行して文字起こしし、テキストファイルを保存する。

### 最初のバージョンのゴール

次のコマンドで録音から文字起こしまで実行できること。

```bash
meeting-cli start
```

基本フロー:

1. 録音用ディレクトリを作成する。
2. Macのマイクから音声を録音する。
3. `Ctrl + C` で録音を停止する。
4. 録音データをWAVファイルとして保存する。
5. Whisperで日本語の文字起こしを行う。
6. 結果をUTF-8のTXTファイルとして保存する。
7. 音声・文字起こしの保存先を表示して終了する。

最初のバージョンでは、リアルタイム文字起こし、話者分離、要約、GUI、クラウドAPI、ZoomやGoogle Meetのシステム音声取得は実装しない。

## 2. 想定環境

- OS: macOS
- 言語: Python 3
- 音声録音: `sounddevice`
- 音声データ処理: `numpy`
- 音声認識: `openai-whisper`
- 音声形式変換・読み込み依存: `ffmpeg`
- CLI引数: Python標準ライブラリの `argparse`
- テスト: `pytest`

Whisperとffmpegはローカル実行する。通常の文字起こしに外部APIキーは不要。ただし、Whisperモデルの初回ダウンロードにはインターネット接続が必要。

## 3. 初期セットアップ

### 3.1 必要なツール

Homebrewが導入済みであることを前提とする。

```bash
brew install ffmpeg
```

Python 3が利用できることを確認する。

```bash
python3 --version
ffmpeg -version
```

`sounddevice` が利用するPortAudioの依存関係でインストールに失敗する場合は、エラーメッセージを確認し、必要に応じてHomebrewで `portaudio` を導入する。

### 3.2 プロジェクト作成

GitHubリポジトリ名は `meeting-cli` とする。

```bash
mkdir meeting-cli
cd meeting-cli
git init
python3 -m venv .venv
source .venv/bin/activate
```

必要なライブラリをインストールする。

```bash
python -m pip install --upgrade pip
python -m pip install sounddevice numpy openai-whisper pytest
```

実際に使用した依存関係を `requirements.txt` に記録する。

```bash
python -m pip freeze > requirements.txt
```

WhisperのインストールはPythonやPyTorchの対応状況によって環境差が出る場合がある。インストール失敗時は、エラーを確認してから互換性のあるバージョンを選ぶ。根拠なく依存関係を一括アップグレードしない。

## 4. 推奨ディレクトリ構成

最初から過剰に抽象化せず、責務ごとに小さく分ける。

```text
meeting-cli/
├── src/
│   └── meeting_cli/
│       ├── __init__.py
│       ├── cli.py          # CLI引数とコマンドの振り分け
│       ├── recorder.py     # マイク録音とWAV保存
│       ├── transcriber.py  # Whisperによる文字起こし
│       └── storage.py      # 保存先・ファイル名の決定
├── tests/
│   ├── test_storage.py
│   ├── test_cli.py
│   └── test_transcriber.py
├── recordings/             # 実行時に作成。Git管理対象外
├── .gitignore
├── pyproject.toml
├── requirements.txt
└── README.md
```

`recordings/` はリポジトリ直下に置く初期設定とする。ユーザーが設定で保存先を変更できる構造にしてもよいが、最初から設定ファイル機能を追加する必要はない。

`.gitignore` には最低限、次を含める。

```gitignore
.venv/
__pycache__/
.pytest_cache/
*.py[cod]
recordings/
dist/
build/
*.egg-info/
```

録音データには機密情報が含まれる可能性があるため、録音ファイルをGitにコミットしない。

## 5. CLI仕様

### 5.1 コマンド

初期バージョンでは、次の2コマンドを実装する。

```bash
meeting-cli start
meeting-cli transcribe <音声ファイルのパス>
```

- `start`: 録音を開始し、停止後に保存と文字起こしを続けて行う。
- `transcribe`: 既存の音声ファイルを文字起こしし、同じファイル名のTXTを出力する。

例:

```bash
meeting-cli start
meeting-cli transcribe recordings/2026-10-12_2100/audio.wav
```

Pythonモジュールとしての開発中は、次のように実行できるようにする。

```bash
python -m meeting_cli.cli start
python -m meeting_cli.cli transcribe recordings/example.wav
```

### 5.2 録音の保存先

録音開始時に日時を使った一意なディレクトリを作成する。

```text
recordings/
└── 2026-10-12_2100-30/
    ├── audio.wav
    └── transcript.txt
```

ディレクトリ名は `YYYY-MM-DD_HHMM-SS` 形式を基本とする。同じ秒に同名ディレクトリが存在する場合は、上書きせず一意な名前にする。

`transcribe` コマンドで既存ファイルを指定した場合は、入力ファイルの拡張子だけを `.txt` に置き換えたパスに出力する。既存のTXTを上書きする場合は、初期バージョンでは上書きの可否を確認するか、エラーとして中止する。無言でデータを上書きしない。

## 6. 実装要件

### 6.1 録音 (`recorder.py`)

- `sounddevice.InputStream` などを使ってマイク入力を取得する。
- サンプルレートは初期値を `16000 Hz`、モノラルにする。利用デバイスとの互換性に問題があれば、デバイスの対応形式を確認して調整する。
- 録音データはメモリにため続けるのではなく、長時間録音でもメモリ使用量が増え続けないよう、チャンク単位でWAVファイルに書き込む設計を優先する。
- WAV書き込みにはPython標準の `wave` モジュールを利用できる。PCM形式・サンプルレート・チャンネル数を正しく設定する。
- 録音開始時に、録音先と停止方法を表示する。
- `Ctrl + C` で録音を正常終了し、ファイルを確実に閉じる。
- 空の録音や、録音開始前のエラーで不正なWAVを残さない。
- マイクが利用できない場合は、原因を簡潔に表示して異常終了する。
- macOSのマイクアクセス許可が必要な場合は、ターミナルまたは実行アプリにマイク権限を付与するよう案内する。
- 録音停止時の `KeyboardInterrupt` を適切に処理し、通常のエラー表示や不要なトレースバックを避ける。

### 6.2 文字起こし (`transcriber.py`)

- `openai-whisper` のPython APIを利用する。
- 初期モデルは `small` とする。実行速度を優先したい場合に `base` などを指定できるようにする。
- `language="ja"` を指定して日本語の文字起こしを行う。
- `verbose` の設定などで処理中の進捗がわかるようにする。
- `result["text"]` を取得し、UTF-8でTXTに保存する。
- モデルは同じプロセス内で何度も使う場合、毎回読み直さないようにする。
- モデルの初回ダウンロードや文字起こしに時間がかかることをユーザーに表示する。
- 入力ファイルが存在しない、空ファイル、読み込みに失敗した場合は、わかりやすいエラーを表示する。
- 文字起こしに失敗しても、元の録音ファイルを削除しない。

### 6.3 保存処理 (`storage.py`)

- 出力先のディレクトリ作成とファイル名決定を担当する。
- ファイルを意図せず上書きしない。
- 保存先は `pathlib.Path` で扱う。
- 文字起こしテキストはUTF-8で保存する。
- 保存成功後に、音声ファイルとテキストファイルのフルパスを表示する。

### 6.4 CLI制御 (`cli.py`)

- `argparse` でサブコマンド `start` と `transcribe` を実装する。
- 録音終了後に文字起こし処理を呼び出す。
- 処理の各段階をユーザーに表示する。例: `録音中...`、`録音を保存しました`、`文字起こし中...`、`完了`。
- 成功時は終了コード `0`、エラー時は `0` 以外を返す。
- 録音を停止しただけで文字起こしが中断されないよう、録音停止処理と文字起こし処理を分ける。
- 文字起こし失敗時にも録音ファイルの保存場所を表示する。

## 7. `meeting-cli` コマンドとしてインストールできるようにする

`pyproject.toml` を作り、開発環境では次のコマンドでCLIを実行できるようにする。

```bash
python -m pip install -e .
```

エントリーポイントは `meeting-cli = "meeting_cli.cli:main"` とする。`src` レイアウトに合わせてパッケージを正しく設定する。

開発中は仮想環境を有効化してコマンドを実行する。普段使いできるようにする場合は、専用の仮想環境にインストールする方法などをREADMEに記載する。システムPythonへ無理にインストールしない。

## 8. テスト方針

テストで実際のマイクやWhisperモデルを必須にしない。依存部分をモックし、通常のテストを短時間で実行できるようにする。

### 必須テスト

- 保存先ディレクトリとファイル名が正しく決まる。
- 既存ファイルを意図せず上書きしない。
- 存在しない音声ファイルを指定すると、わかりやすいエラーになる。
- Whisperの戻り値がUTF-8のTXTに保存される。
- 文字起こしの失敗時に録音ファイルが残る。
- `Ctrl + C` 相当の停止時に録音ファイルが正常に閉じられる。
- CLIの不正な引数で適切に失敗する。

### 手動テスト

1. マイクの使用許可を確認する。
2. `meeting-cli start` を実行する。
3. 10〜20秒ほど日本語を話す。
4. `Ctrl + C` を押す。
5. WAVファイルが再生できることを確認する。
6. TXTが作成され、内容が文字起こしされていることを確認する。
7. `meeting-cli transcribe <WAVのパス>` で再度文字起こしできることを確認する。
8. マイク権限がない場合や入力ファイルがない場合に、エラーが適切に表示されることを確認する。

## 10. 実装の進め方

以下の順番で小さく実装し、各段階でテストする。

1. リポジトリ、仮想環境、依存関係、`.gitignore` を整備する。
2. `storage.py` と保存先のユニットテストを実装する。
3. `recorder.py` を実装し、短時間の録音をWAVとして保存できるようにする。
4. `transcriber.py` を実装し、既存の音声ファイルをTXTに変換できるようにする。
5. `cli.py` で `start` と `transcribe` を接続する。
6. `pyproject.toml` のエントリーポイントを設定する。
7. テストを実行し、手動テストを行う。
8. READMEを作成する。
9. 最終的に新しい仮想環境でもセットアップ手順どおりに動くことを確認する。

各段階で必要なテストを追加し、失敗の原因を特定してから次に進む。一度にすべてを生成して動作確認を省略しない。

## 11. 実装上の注意

- Whisperのモデルファイルは容量が大きい。初回ダウンロードが発生することを明示する。
- 録音の音質はマイク、設置場所、周囲のノイズに左右される。
- Macのマイク入力を録音するだけでは、オンライン会議の相手の音声を必ずしも取得できない。
- 長時間録音に備え、録音データをメモリに無制限に蓄積しない。
- `Ctrl + C` を受けたとき、録音ファイルを閉じて保存してから文字起こしに進む。
- 予期しない終了やOSの強制終了では、ファイルが完全に保存されない可能性があることをREADMEに記載する。
- 会議音声は機密情報を含む可能性がある。保存場所、ファイル共有、削除方法に配慮する。
- 依頼されていない機能や不要な複雑さを追加しない。
